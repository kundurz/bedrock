# Table ADT

We can think of a table as an abstract storage device composed of entries. 

Each entry is known as an `ordered pair` and contains two things:
1) A key, used to uniquely identify the entry
2) A piece of information associated with the key, often referred to as a value.

In a case where the number of possible keys is relatively small, you can pre-reserve states in the table. 

In other cases, the number of possible keys increases to a lot. Imagine you're using employee number, where you will only ever resereve a fraction of all possible keys.
